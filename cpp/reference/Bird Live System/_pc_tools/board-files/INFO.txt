TI SK-AM62 BIRD DETECTION - BOARD SELF-GUIDE
(no PC needed: the whole pipeline lives on this board)

WHAT THIS BOARD DOES
  Pulls the phone-camera (DroidCam) MJPEG stream over WiFi, runs
  YOLOv8 (best.onnx, cv2.dnn) on-board, draws boxes, and hosts the
  live dashboard itself on port 8888. No PC required for operation.

ADDRESSES
  Dashboard (open from ANY device on the WiFi):
      http://192.168.1.22:8888/
  Endpoints on port 8888:
      /           dashboard   (light UI, no heavy streaming)
      /frame.jpg  latest raw camera frame
      /det.jpg    latest annotated result (also /live_det.jpg)
      /meta.json  detections JSON  (n, infer_ms, dets[])
      /phone      camera link status (connected, frame_age, attempts)
      /stream     full-screen MJPEG stream (throttled to 1 fps)
      /ping       health check ("board-ok")
  SSH from any machine:   ssh tibird   -> root@192.168.1.22
  Serial console: COM6 @ 115200, login root / password tiroot
  Phone camera (DroidCam): 192.168.1.3 port 4747

FILES  (all under /home/root/bird/)
  board_camera_server.py  MAIN program (birdboard.service):
                          capture thread + inference thread + web server
  board_detection.py      YOLOv8 ONNX runner (model cached after first load;
                          in-process mode: run(...) returns the meta dict)
  best.onnx               the trained model
  camera_url.txt          camera source - EDIT THIS FILE to change cameras;
                          re-read automatically on every reconnect attempt
  frame.jpg               latest raw frame (written by capture)
  live_det.jpg            latest annotated frame
  meta.json               latest detections metadata
  INFO.txt                this file

SERVICE (systemd)
  systemctl status birdboard      the whole pipeline (enabled at boot)
  systemctl restart birdboard
  journalctl -u birdboard -n 50   recent logs
  Enabled services:
      wifi-up.service   WiFi link at BOOT (starts early: page ~25 s after power)
      dropbird.service  RETIRED - the board image's own dropbear serves SSH
  SSH is provided by the built-in dropbear (PID shown by: netstat -tlnp | grep :22)

BOOT, timing and behavior
  Power on -> ~25 s -> dashboard reachable; camera re-grabs automatically
  (retries every 2 s until DroidCam answers; keep the app on WiFi Server).
  systemd-networkd-wait-online is masked on purpose: it stalls ~2 min
  waiting for the unplugged Ethernet port on this WiFi-only board.

CAMERA RULES
  * DroidCam serves ONE client at a time; the board is that client.
    Do NOT also run the PC bridge (camera_bridge.py) at the same time.
  * Keep the DroidCam app open on the WiFi Server screen.
  * Phone screen on/unlocked keeps DroidCam streaming; if it stalls,
    the board detects "no frames" and reconnects automatically.
  * Camera link down -> board retries every 2 s (status in /phone).

CHANGE THE CAMERA SOURCE  (e.g. phone IP changed, or CSI camera later)
  1) find the new source (DroidCam shows its IP; CSI camera = /dev/video0)
  2) echo http://PHONE_IP:4747/video > /home/root/bird/camera_url.txt
     (or write /dev/video0 there for the CSI camera)
  No restart needed: the URL is re-read at every reconnect attempt.
